grove · docs

desired state vs actual state

grove cultivates git worktrees. manifest.toml declares desired state, git on disk is actual state, and grove converges them additively — never deleting what it did not create. One Rust workspace, one binary; grove serve is the daemon, and every status it holds is a cache re-derived from disk.

The root layout

Two trees under $GROVE_HOME, one entry per root in each: roots/<owner>/<repo>/ holds everything grove owns, code/<owner>/<repo>/ holds checkouts and only checkouts.

Engine lanes

One engine per declared root drives convergence through that root's lane; the watcher only discovers and announces. Events, never a clock. Detail: engine.md.

Self-update

grove up installs into an immutable versions/<v>/ and moves only current. The flip lands before the health gate answers, so the verdict it owes is written first, as the pending marker. Detail: updates.md.

Decisions

Shipped designs, the choice each made and why. The mechanics live in the reference docs; history is in git.

The install is not the workspace · v0.2.0, ea9629a

Two roots with opposite lifecycles: $GROVE_INSTALL (default ~/.local/share/grove — versions/, current, previous, channel, pending, update.lock) is disposable and owned by grove up; $GROVE_HOME (default ~/.grove) is the workspace and nothing else. Each has one resolution (grove_ops::install_home, home), and the launcher passes GROVE_INSTALL to a served daemon. Why: uninstall used to delete every checkout with the binary, and a second home had to carry its own install. uninstall.sh now removes the workspace only behind --purge; a stale layout is the doctor finding install-under-home, whose fix line is the four-line move.

The trunk is a branch, named by that branch · v0.2.0, ea9629a

Every checkout directory is worktrees::name_for(branch); the trunk is the worktree the manifest's optional trunk key points at, else the bare's HEAD. The manifest key is desired state, the bare's HEAD actual state, and reconcile sets one from the other (git::set_head). Changing the trunk is a manifest edit: the new trunk checkout is ensured, shares repoint, and the old trunk stays on disk as an ordinary worktree — no trunk change deletes anything. Why: a hidden role-named .trunk beside branch-named worktrees was two naming schemes, and some repos integrate on a branch other than the remote default. The wire carries trunk_branch.

Reconcile refuses a legacy or occupied root · v0.2.2, b43745e

realize never clones into a directory it does not own: a root in any older layout is a Failed outcome naming the generation and the remedy (grove doctor --fix), and a code dir holding anything but .DS_Store is refused naming the entries. Migration happens only in doctor --fix, where the operator asked for it; the error reaches RootView.error and grove tree list, and the doctor route nudges a migrated root to re-derive. Why: a daemon booted over sixteen pre-0.2 roots re-cloned each beside its legacy layout — reconcile never consulted the doctor finding that already knew.

A root holds checkouts and nothing else · v0.3.0, 99b7299

A root is a declared repo — [roots."o/r"] in the manifest, roots/o/r/ on disk (root_dir) holding bare/, pool/slot-N and the cloning marker; its code dir is code/o/r/ (code_dir). One word, one thing. clone remove deletes both, so nothing of a root survives elsewhere; adopt walks roots/, and checkouts without a root are the report-only finding orphan-code. One detector (layout::legacy) names all three layout generations and doctor --fix migrates any of them to v3 idempotently, refusing a half-moved root rather than guessing. The root view gains root (shown under --verbose), and grove workspace writes a .code-workspace of every checkout on demand. Why: grove's private .bare and .pool sat in every editor explorer beside the operator's checkouts, and every rule had to say "except grove's own entries".

A stopped engine writes nothing new · #2

Engine::stop raises a flag the reconcile lane job reads before its clone-permit try, so a queued reconcile of a stopped engine never begins — no permit, no realize. grove-ops work already running cannot be cancelled: a clone mid-transfer finishes and reports to a mailbox nobody reads. The remove ordering stays ※ delete-before-undeclare: undeclaring first would let adopt, which runs off the lane, re-declare the still-present bare, while the window it was to close never reaches reconcile — remove holds the root's lane, and reconcile_one re-reads the declaration under it. Why: a reconcile queued behind a stopped engine (a daemon shutting down) still cloned the root.

Next

What is open, in order. Locations are symbols and ※ anchors, never line numbers.

  1. Heal a stale failed by its cause, not by disk. apply_reconcile maps Applied{status: failed} to degraded, and a blanket Derive(disk) there would report ready over a genuine trunk conflict (a trunk moved onto another branch's checkout: disk_status finds a trunk, and the view shows error only while degraded). The stale case is the in-flight back-off finding: make the CLI's clone finishing raise an event the engine already re-derives on.
  2. Work the open sweep findings, highest first.

Open sweep findings

The s-20261012T0155Z gigasweep confirmed 21 defects by probe and the s-20261019T0455Z sweep three more, all fixed on trunk. Open, highest first:

  1. is_under_trunk forgets the old trunk (confirmed, low). After a trunk change (main → canary), share links laid through ../main/ read as foreign.
  2. RootView.url and error are served unredacted (plausible). The Host guard closes the remote read path; local readers still see clone URLs, including any embedded credentials.
  3. grove off checks for any grove daemon, not this home's (plausible, medium). It can shut down another home's daemon on the same bind.
  4. An in-flight back-off is never retried (plausible, low). A daemon booting during an offline CLI clone reports failed: … in flight; the CLI finishing raises no watched event, so status stays failed until the next manifest change. Same shape as Next 3.
  5. Manifest writes don't fsync (plausible, low). write_doc renames manifest.toml.tmp without fsyncing the file or its directory.
  6. Slugs keep their case (plausible, low). slug_from_url of …/Foo/bar and …/foo/bar mints two manifest keys that share one directory on case-insensitive APFS.
  7. version_key misorders (plausible, low; update/layout.rs). +build metadata folds into the core numbers (0.4.0+1 > 0.4.0) and prereleases compare by number before label (-canary.10 > -rc.1). Pruning order only: current and previous are protected.
  8. logs::redact cuts at the first @ (plausible, low; grove-daemon/src/logs.rs), telemetry::redact_url at the last, so a raw @ in a password leaves its tail in the ring.
  9. Only origin counts as a branch's remote (plausible, low; git::branch_target, branch_exists). A branch living only on a remote the operator added (upstream/x) is minted off HEAD, untracked. grove clones only origin.

Unattended shifts

Sandbox denials, not regressions; gate them on a host run.

  • cargo nextest fails ~118 tests in the shift sandbox: those binding loopback ports (EPERM), the ps-based process_start_time_is_stable_for_a_live_pid, and on the ci profile the FSEvents-backed watcher::tests::slow_an_fs_write_to_the_manifest_announces.
  • Coverage is measured under shift-test (cargo llvm-cov nextest --workspace --summary-only, loopback allowed there): 93.09 % lines at the s-20261019T0455Z landing.
  • test/install_smoke.sh needs a mktemp shim on PATH that roots templates under $TMPDIR: macOS mktemp -d ignores TMPDIR and the sandbox denies /var/folders.
