grove · docs

desired state vs actual state

grove cultivates git worktrees. manifest.toml declares desired state, git on disk is actual state, and grove converges them additively — never deleting what it did not create. One binary; grove serve is the daemon, and every status it holds is a cache re-derived from disk.

The root layout

Two trees under $GROVE_HOME, one entry per root in each: roots/<owner>/<repo>/ holds everything grove owns, code/<owner>/<repo>/ holds checkouts and only checkouts.

Engine lanes

One engine per declared root drives convergence through that root's lane; the watcher only discovers and announces. Events, never a clock. Detail: engine.

Install and upgrade

hotswap, linked into the binary, installs and swaps the version; packslip verifies each release against grove's signer. Every merge to main is a GitHub Release YYYY.M.N, macOS arm64 only.

grove setup           # install, load agents
grove upgrade         # every 900 s by agent
grove upgrade --check # or --back, --retry
grove setup --remove  # ~/.grove stays

grove setup installs the latest release into ~/.local/share/hotswap/grove/<V>/ when none is active — run from a checkout too: the release is linked, never the checkout's binary — links ~/.local/bin/grove through current, and runs two launchd agents on that link: grove's dev.gigantic.grove keeps grove serve alive, and hotswap's own dev.gigantic.grove.upgrade runs grove upgrade every 900 s. The server's PATH keeps mise's shims dir, when one exists, after ~/.local/bin, for what git runs (hooks, git-lfs). An upgrade installs the newer release, repoints current, re-runs setup, then swaps the server with one launchctl kickstart -k, whose SIGTERM runs the daemon's bounded drain. An agent launchd loaded at login carries a managed launch constraint, which the first spawn after a swap violates; hotswap detects it (managed LWCR in launchctl print) and boots the agent out and back in from its plist instead of kicking it, which drains the same way. The upgrade smokes grove --version and GET /api/health, and red rolls back. The record is ~/.local/state/hotswap/grove.json; setup --remove drops it, the agents, the link and the layout.

Decisions

Shipped designs, the choice each made and why.

hotswap installs and swaps · 2026-11-17

grove ships as a packslip release; setup and upgrade are hotswap's tool contract, shared with sandman and routines, and neither needs mise. The versions live in ~/.local/share/hotswap/grove, outside $GROVE_HOME, so the workspace holds nothing an install can delete; an install tree inside it is the doctor finding install-under-home. Why: one install and swap path for every gigantic tool, on a machine with nothing else.

Every stop signal drains · 2026-11-11

SIGTERM, SIGINT and SIGHUP run the shutdown route's drain inside a budget that fits the server agent's ExitTimeOut (10 s), then exit 0 with an exit line in serve.log. A swap is one kickstart -k, and a launchd-owned daemon stops by bootout. Why: a separate drain raced KeepAlive's respawn and refused the swap on every tick.

The trunk is a branch, named by that branch · v0.2.0, ea9629a

Every checkout directory is worktrees::name_for(branch); the trunk is the worktree the manifest's optional trunk key points at, else the bare's HEAD. The manifest key is desired state, the bare's HEAD actual state, and reconcile sets one from the other (git::set_head). Changing the trunk is a manifest edit: the new trunk checkout is ensured, shares repoint, and the old trunk stays on disk as an ordinary worktree. Why: a hidden role-named .trunk beside branch-named worktrees was two naming schemes, and some repos integrate on a branch other than the remote default. The wire carries trunk_branch.

Reconcile refuses a legacy or occupied root · v0.2.2, b43745e

realize never clones into a directory it does not own: a root in any older layout is a Failed outcome naming the generation and the remedy (grove doctor --fix), and a code dir holding anything but .DS_Store is refused naming the entries. Migration happens only in doctor --fix, where the operator asked for it; the error reaches RootView.error and grove tree list, and the doctor route nudges a migrated root to re-derive. Why: a daemon booted over legacy roots re-cloned each beside its old layout.

A root holds checkouts and nothing else · v0.3.0, 99b7299

A root is a declared repo — [roots."o/r"] in the manifest, roots/o/r/ on disk (root_dir) holding bare/, pool/slot-N and the cloning marker; its code dir is code/o/r/ (code_dir). clone remove deletes both, so nothing of a root survives elsewhere; adopt walks roots/, and checkouts without a root are the report-only finding orphan-code. One detector (layout::legacy) names all three layout generations and doctor --fix migrates any of them to v3 idempotently, refusing a half-moved root rather than guessing. The root view gains root (shown under --verbose), and grove workspace writes a .code-workspace of every checkout on demand. Why: grove's private entries sat in every editor explorer beside the operator's checkouts, and every rule had to except them.

A stopped engine writes nothing new · #2

Engine::stop raises a flag the reconcile lane job reads before its clone-permit try, so a queued reconcile of a stopped engine never begins. grove-ops work already running cannot be cancelled: a clone mid-transfer finishes and reports to a mailbox nobody reads. The remove ordering stays ※ delete-before-undeclare: undeclaring first would let adopt, which runs off the lane, re-declare the still-present bare, while the window it was to close never reaches reconcile — remove holds the root's lane, and reconcile_one re-reads the declaration under it. Why: a reconcile queued behind a daemon shutting down still cloned the root.

Open sweep findings

Highest first.

  1. A symlink share whose source is a directory refuses every trunk change (confirmed, medium; env.rs carry seed). read_present bails on a directory, which source_op accepts everywhere else; the fix is the directory seeding rule above.
  2. Only origin counts as a branch's remote (plausible, low; git::branch_target, branch_exists). A branch living only on a remote the operator added (upstream/x) is minted off HEAD, untracked. Waits on proposal:jgeschwendt/grove:only-origin-counts.
  3. The old trunk's own share source reads as a conflict after a trunk change (confirmed, low; c079973). The ex-trunk is adopted as a worktree and its real .env is a conflict row, so grove doctor exits 5 after any trunk change.
  4. A refused trunk change still links new worktrees through the occupant (plausible, low; c079973). While a worktree occupies the new trunk's directory, ordinary passes take that checkout as the trunk; a symlink source there reads ok (env.rs source classification), so worktrees created in that window link into the user's checkout.
  5. doctor --fix --force rewrites the old trunk's source during a held trunk change (plausible, low). The ex-trunk is listed as an undeclared worktree, so the link pass backs up main/.env to .env.grove-bak and links it to ../canary/.env before HEAD moves. Fix: skip the bare's HEAD checkout in link/copy/GC while pending.
  6. A carry holds on an in-trunk link whose target the new trunk will have (plausible, low). .k1 -> .real is held even when .real is tracked or itself a declared share, until the operator re-creates it; the check is lexical.
